# Python／Circom ハイブリッド化 変更記録

各節は、そのまま進捗報告のスクリーンショットに使える長さと構成にしている。

## 1. コミットメント仕様の固定

生CSIを表すC0とVMD入力を表すC1について、Poseidonの入力順、符号付き整数の
オフセット、量子化スケール、行列の並び順、ドメインタグ、nonceを固定した。
PythonとCircomで別実装を持たず、`circomlibjs`を共通の参照実装として使用する。
Docker起動時にも回路の自動コンパイル設定とは独立してZKPのNode依存を準備する。

```python
nonce = new_commitment_nonce()
c0 = commit_raw_csi(csi_matrix, nonce)
c1 = commit_vmd_input(certificate_input["vmdInput"], nonce)
```

詳細仕様: `COMMITMENT_DESIGN.md`

## 2. C1拘束付き証明書回路

既存回路を変更せず、`csi_breathing_certificate_committed`を追加した。秘密の
`vmdInput`から回路内でC1を再計算し、公開コミットメントとの一致を強制する。
nonceは秘密入力のままで、APIレスポンスや実験記録には出力しない。

```circom
encodedVmdInput[i] <== vmdInput[i] + 1024;
commitmentStep[i].inputs[0] <== commitmentState[i];
commitmentStep[i].inputs[1] <== encodedVmdInput[i];
commitmentState[T] === vmdCommitment;
```

新API: `POST /api/v2/breathing/analyze-committed`

## 6. 前処理検証の段階的追加

32サンプル×8特徴の量子化PCA射影回路を追加した。入力行列と重みをPoseidonへ拘束し、
各内積を回路内で厳密に検証して射影結果のコミットメントを公開する。8特徴はPCA重みの
絶対値上位から選び、元のPython PCA波形との相関を診断値として保存する。
このwitnessはベンチマーク実行時だけ生成し、既存の通常解析APIの処理時間・レスポンスは変えない。

```circom
projectionTerm[t][0] <== centeredX[t][0] * weights[0];
for (var n = 1; n < N; n++) {
    projectionTerm[t][n] <== centeredX[t][n] * weights[n];
    projectionPartial[t][n] <== projectionPartial[t][n-1] + projectionTerm[t][n];
}
projected[t] <== projectionPartial[t][N-1];
```

この回路が保証するのは縮約・量子化後の射影であり、SNR選択、バンドパス、最大固有値性は
まだ保証範囲外である。限界を隠さず、相関と証明コストを見て次の拡張を判断できるようにした。

## 8. 初回実データ解析のスライド反映

研究モードのアップロードAPIで受信した初回実データについて、入力規模、Python推定、
Lomb–Scargle推定、既存Groth16証明時間を進捗報告へ追加した。VMDの15.19 BPMと
Lomb–Scargleの19.02 BPMには3.83 BPMの差があり、正解BPMが未登録のため精度指標は
まだ確定できない。既存アップロード経路と、新しいC1拘束付き4方式ベンチマークを
混同しないよう、次に必要な処理も同じスライドへ明記した。

```text
CSI: 5,531 frames × 980 features
Python VMD:       15.19 BPM / 5.974 s
Lomb–Scargle:     19.02 BPM / 1.044 s
Existing Groth16: 14.496 s / isNormal=true
Ground truth:     not registered
```

同じバックグラウンド処理ではLomb–Scargle証明生成が9分を超え、確認時点の最大で
コンテナの14.58 GiB（上限15.62 GiB、約93.4%）を使用した。この実測により、
大規模回路をそのままエッジへ移すのではなく、縮約回路とハイブリッド境界を比較する
必要性がより明確になった。

その後、測定者が目視で数えた約19.8 BPMを評価用参考値として保存した。機械計測では
ないため厳密なground truthとはせず、スライドにも手動カウントであることを明記した。
参考値との差はPython VMDが−4.61 BPM、Lomb–Scargleが−0.78 BPMだった。1件だけの結果で
方式の優劣やMAE／RMSEを結論づけず、今後の反復測定で集計する。

```text
Manual reference: 19.80 BPM
Python VMD:       15.19 BPM (error -4.61 BPM)
Lomb–Scargle:     19.02 BPM (error -0.78 BPM)
```

大規模証明を含むバックグラウンド処理は、アップロードから約17分30秒後に終了した。
従来の`csi_breathing_certificate`はwitness 1.111秒、proof 5.627秒、verify 7.729秒、
合計14.467秒で検証に成功した。一方、`csi_lomb_scargle_normality`は長時間の証明生成後、
検証コマンドが設定値の10秒でタイムアウトしたため、この証明ブランチはfailedになった。

```text
Database processing status: completed
Internal analysis status:    partial
breathing_certificate:       completed / verified
lomb_scargle_normality:      failed / verify timeout (10 s)
```

ここでDBの`completed`はバックグラウンドタスク自体が終了したことを表す。全証明の成功を
表す値ではないため、進捗報告では内部の`partial`と各証明ブランチを併記する。

## 10. 大規模証明のタイムアウトなし再計測

`csi_lomb_scargle_normality`だけ検証タイムアウトを無効化し、通常回路は60秒の停止保護を
維持するようにした。同じ保存済みCSIを再処理した結果、証明生成と検証の両方が完了した。

| 段階 | 実測値 |
|---|---:|
| 制約数 | 7,503,485 |
| witness生成 | 10.111秒 |
| proof生成 | 1,102.626秒 |
| verify | 8.721秒 |
| ZKP合計 | 1,121.458秒 |
| 検証結果 | `isValid=true`、`isNormal=true` |

```python
def _verification_timeout_seconds(self) -> Optional[int]:
    if self.circuit_name in self.LARGE_CIRCUITS:
        return None
    return self.DEFAULT_VERIFICATION_TIMEOUT_SECONDS
```

最大確認メモリは14.59 GiB／15.62 GiBだった。検証は10秒未満で終わり、処理時間の大半は
約18分23秒のproof生成だった。再処理時はVMD近似回路の成果物がstaleだったため、外側の
解析状態は`partial`だが、Lomb–Scargle証明ブランチ自体は生成・検証とも成功している。
