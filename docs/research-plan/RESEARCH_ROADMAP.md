# 検証可能な非接触呼吸監視システム — 研究計画提案書

作成日: 2026-07-20
ステータス: 提案（コード変更なし）

## 1. 背景と現在地

本リポジトリは Wi-Fi CSI による非接触呼吸推定（5-1 パイプライン:
振幅行列 → SNRサブキャリア選択 → バンドパス → PCA → VMD → 6–22bpm 正常判定）に対し、
ZKP による検証可能性を付与するシステムである。現状の資産:

| 資産 | 状態 |
|------|------|
| `zkp/circuits/csi_breathing_certificate.circom` | 実装済み。VMD の「計算」ではなく「出力の性質」（再構成性・狭帯域性・正常帯域）を検証する証明書方式 |
| `zkp/circuits/csi_full_similarity.circom` | 本番フローで使用中（コサイン類似度） |
| RISC Zero zkVM（`zkvm/`） | 実装済みだが**開発終了**。実データでの証明時間が非実用的 |
| 生CSIの真正性保証（デバイス署名等） | **未実装**（`docs/ZKP_PIPELINE_EXTENSION_IDEAS.md` テーマ2） |

技術スタックは今後 **Python + Circom を主軸**とする。zkVM は今後開発しないが、
実測した証明時間は「再実行証明が非実用的である」ことの根拠データとして論文で使用する
（数値・測定条件は破棄しないこと）。

## 2. 研究戦略の全体像

Wi-Fi CSI 呼吸推定そのものは成熟分野であり、信号処理単体での新規性は出しにくい。
本計画は「**検証可能性 × 非接触バイタルセンシング**」の交差点を 3 フェーズで攻める:

```
Phase 1: 証明書方式は「何を」保証するのか
         → 健全性ギャップの形式化・攻撃探索・回路硬化
Phase 2: 「誰の・いつの」データかを保証する
         → デバイス署名 + Poseidon コミットメント + 段間連鎖 + オンチェーン事前コミット
Phase 3: 「継続的に」保証する
         → folding (Nova/Sonobe) によるスライディングウィンドウ連続監視
```

順序は固定。Phase 1 で回路を硬化させてから Phase 2/3 に載せないと、
後段の主張が「偽造可能な証明書を署名付きデータに紐付けた」だけになる。

### 論文マッピング

- **論文①**（Phase 1 単独）: 反復最適化を含む信号分解（VMD等）の
  certificate-based ZK verification の健全性ギャップの形式化と較正手法。
  応用暗号・セキュリティ系。
- **論文②**（Phase 1+2、Phase 3 が入れば強化）: センサからチェーンまで
  暗号学的に連結された初の検証可能・非接触バイタル監視システム。
  セキュリティ系 or ブロックチェーン応用系。

## 3. フェーズ概要

### Phase 1: 健全性ギャップの形式化と攻撃評価

**命題**: VMD は ZK 回路で再実行できないため性質検証（certificate）に置き換えたが、
そのとき悪意ある証明者に残される自由度はどれだけか。

- 回路制約の Python 忠実再実装（整数・固定小数点セマンティクス込み）
- 攻撃探索: 特に「**選択モードのエネルギー下限制約が存在しない**」仮説の検証
  （異常信号の大部分を他モードに押し込み、微小な正常帯域モードを捏造して選択すれば
  自明に通る可能性が高い）
- 閾値掃引による「正規データ証明成功率 vs 偽造成功率」トレードオフ曲線
- 対策制約（モードエネルギー下限等）を加えた硬化版回路の生成

→ 詳細指示: `PHASE1_BRIEF.md`

### Phase 2: end-to-end 真正性チェーン

**命題**: 測定デバイスからオンチェーン記録まで全段が暗号学的に連結された
検証可能バイタル監視。

- 生CSI（振幅行列）の Poseidon コミットメントを回路公開入力化
- 回路を 2 分割し中間コミットメントで連鎖:
  - 回路①「前処理」: コミット済み行列 → サブキャリア選択検証 → バンドパス(固定FIR)
    → PCA witness 検証（`C·v ≈ λv` + 射影一致） → `Poseidon(vmdInput)` を公開
  - 回路②「証明書」: Phase 1 硬化版 + `Poseidon(vmdInput)` 一致検証
- エッジデバイス署名（回路外検証）+ `ZKProofRegistry` 拡張によるコミット・リビール
- Phase 1 の攻撃評価を「入力拘束あり」設定で再実行し耐性向上を定量化

→ 詳細指示: `PHASE2_BRIEF.md`

### Phase 3: folding による連続監視

**命題**: 一晩分のウィンドウ毎解析を折り畳み証明で累積し、
「全区間正常」「異常ウィンドウ数 ≤ k」（≒検証可能な AHI 推定）を単一証明で示す。

- 第一候補: Sonobe（Nova/HyperNova, Circom フロントエンド対応）
- **着手前に 1〜2 週間の feasibility 実験で Go/No-Go 判断**（既存証明書回路 1 個を
  ステップ関数として折り畳めるか）
- フォールバック: ウィンドウ毎 Groth16 証明の Merkle 集約

→ 詳細指示: `PHASE3_BRIEF.md`

## 4. スケジュール目安

| 時期 | 内容 | 成果物 |
|------|------|--------|
| 〜1ヶ月 | Phase 1: 制約チェッカ + 攻撃探索 + エネルギー下限欠如仮説の検証 | 攻撃例・トレードオフ曲線 |
| 〜2ヶ月 | Phase 1: 回路硬化 + 較正、論文①ドラフト | 硬化版回路 |
| 2〜4ヶ月 | Phase 2: コミットメント設計 → 回路分割 → エッジ署名 → Registry 拡張 | end-to-end プロトタイプ |
| 3ヶ月目 | Phase 3 feasibility 実験（並行、1〜2週） | Go/No-Go 判断 |
| 4ヶ月〜 | Phase 3 本実装 or フォールバック、論文② | 連続監視プロトタイプ |

## 5. スコープ外・凍結事項

- **zkVM（RISC Zero）の追加開発は行わない**。`zkvm/` は削除せず凍結。
  実測証明時間はモチベーションデータとして保全する。
- 本番フロー（`csi_full_similarity` / CSIアップロード）は各フェーズで変更しない。
  新機能は別エンドポイント・別回路として追加する。
- TEE ベースのキャプチャ証明は将来課題として論文で言及するに留める。

## 6. リスクと対応

| リスク | 対応 |
|--------|------|
| Phase 1 攻撃探索で偽造が「できない」結果に終わる | それ自体が閾値の妥当性の証拠になり較正論文として成立。ただしエネルギー下限欠如は構造的な穴なので、少なくとも 1 つの攻撃例は得られる見込みが高い |
| PCA witness 検証の制約数が想定超過（目安 T×N² ≈ 13.5万） | N（SNR選択後サブキャリア数）を削る / 前処理回路のカバー範囲を PCA 以降に縮める |
| Sonobe の成熟度不足・固定小数点回路との相性 | feasibility 実験で早期判断し、Merkle 集約へフォールバック |
| 実データ（異常呼吸）の不足 | 正常データへの摂動 + 合成異常（無呼吸区間挿入・頻呼吸）で代替。論文では限界として明記 |
