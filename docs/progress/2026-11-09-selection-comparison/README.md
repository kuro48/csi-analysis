## 実データの選択列

列番号は0始まり。整数64のPythonは全件Circomと一致し、下表の実数64でも変わらなかった。
全点は、既存パーサーが選ぶ最頻CSI幅の行からミリ秒重複を除いたもの。

| CSI | 全点数 / 候補列数 | Circom | Python 同式・実数64 | Python 同式・全点 | Python 周期性・全点 |
|---|---:|---:|---:|---:|---:|
| csi_20260519_114943 | 150 / 4004 | 721 | 721 | 723 | 1865 |
| csi_sample_base | 270 / 53 | 44 | 44 | 30 | 39 |
| csi_sample_base2 | 4436 / 4004 | 3101 | 3101 | 3037 | 281 |
| csi_sample_main | 275 / 4004 | 505 | 505 | 506 | 2414 |
| csi_sample_main2 | 4645 / 4004 | 2372 | 2372 | 2376 | 1386 |

- 同一64点・同一式の整数計算: **5/5一致**。今回の入力では回路の実装不一致は検出されなかった。
- 同じ64行で整数化前の実数を使用: **5/5一致**。整数化による選択列の変化はなかった。
- 同じ式で全点を使用: **0/5一致**。64点への間引きでランキングが変わる。
- 周期性による選択: 整数64点・全点とも **0/5一致**。目的関数自体が異なる。

一致率は呼吸の正解率ではない。隣接した列が選ばれた場合もあるが、物理toneやアンテナ組の
対応を別途確定していないため、列番号の近さだけから性能が同じとは判断しない。

例として `csi_20260519_114943` の列721は、電力の変動係数の二乗 `V/S²` が
64点では **0.9843**、全150点では **1.0883** だった。
適格条件が `V/S² <= 1` のため、全点では候補から除外される。
64点化の影響は順位の微差だけでなく、適格性の判定にも及ぶ。

全点の周期性基準で選んだ列でも、推定ピークが呼吸に由来するとは確認できない。
例えば同ファイルの列1865は、正常帯域内の説明分散率は約0.237だが、
探索全域での最大ピークは約0.072 Hzと正常帯域の外にある。
Pythonの出力を無条件に「正解」にはできない。

## 合成データでの正解列選択

各条件4件、合計12件。正解は「既知の呼吸周波数の信号を埋め込んだ列」。
`clean` にも振幅雑音を含む。条件の詳細は手順書と `synthetic_cases()` に記載した。

| 条件 | Circom 現行スコア | Python 同式・整数64 | Python 周期性・整数64 | Python 周期性・全点 |
|---|---:|---:|---:|---:|
| 振幅雑音あり (`clean`) | 0/4 | 0/4 | 4/4 | 4/4 |
| 大きな低周波変動 (`slow_drift`) | 0/4 | 0/4 | 4/4 | 4/4 |
| 呼吸帯域内の周期ノイズ (`in_band_interference`) | 0/4 | 0/4 | 0/4 | 0/4 |

同じ64点でも周期性を使うPythonは前2条件で改善した。
これは「Pythonという言語の方が高精度」というより、**呼吸向けの目的関数の違い**を示す。
一方、呼吸帯域内の強い周期ノイズでは両方法とも失敗した。
現行スコアをPythonへ移しても、その弱点は解消しない。

この合成12件は弱点を確認するための固定条件であり、実際の患者での正解率や
代表的なデータ分布に対する精度として使用してはいけない。
実測データに同期した正解ラベルはユーザーにも未確認で、実際の呼吸判定精度は未確定。
