# Python／Circom ハイブリッド設計 議論記録

## 2026-10-05 — 処理ごとのコミットメントと遷移証明

### ユーザーの意図

> 哀愁的にはそれぞれの処理の正しさを証明したいから、理想は各処理ごとに
> コミットメントハッシュを生成してCircomで証明するのが理想。

文脈上の「哀愁的には」は「最終的には」の意図として整理した。最終目標は、単に
最終BPMだけを証明するのではなく、生CSIから呼吸数を得るまでの各処理が規定どおり
実行されたことを段階的に証明することである。

### 合意した結論

各中間値のPoseidonコミットメントを生成するだけでは、値が後から変わっていないことは
拘束できても、前段から後段への計算が正しかったことは証明できない。各ステージには、
入力コミットメントと出力コミットメントを同時に拘束する遷移証明が必要である。

```text
C_i     = Poseidon(stage_i, nonce_i, metadata_i, X_i)
C_(i+1) = Poseidon(stage_(i+1), nonce_(i+1), metadata_(i+1), X_(i+1))

π_i = ZKProof(
  C_i,
  C_(i+1),
  configHash_i;
  X_i,
  X_(i+1),
  nonce_i,
  nonce_(i+1)
)

制約: X_(i+1) = f_i(X_i, config_i)
```

各証明`π_i`は、次の3点を同時に保証する。

1. 秘密入力`X_i`が公開された入力コミットメント`C_i`と一致する。
2. 出力`X_(i+1)`が規定された処理`f_i`から正しく計算される。
3. 計算結果が公開された出力コミットメント`C_(i+1)`と一致する。

### 理想的な証明チェーン

```text
生CSI
  │ C0
  ▼
[π0: 複素CSI → 振幅]
  │ C1
  ▼
[π1: 振幅 → SNR計算・特徴選択]
  │ C2
  ▼
[π2: バンドパスフィルタ]
  │ C3
  ▼
[π3: 中心化・PCA]
  │ C4
  ▼
[π4: PCA射影]
  │ C5
  ▼
[π5: VMD近似・モード選択]
  │ C6
  ▼
[π6: 周波数解析・ピーク検出]
  │ C7
  ▼
呼吸数BPM
```

次段の入力コミットメントは、必ず前段の出力コミットメントと一致させる。

```text
π0.outputCommitment == π1.inputCommitment
π1.outputCommitment == π2.inputCommitment
π2.outputCommitment == π3.inputCommitment
```

これにより、小さな回路へ分割しても、チェーン全体としてEnd-to-Endの計算過程を
検証できる。最終的には複数証明を再帰証明または集約証明で1つにまとめることもできる。

### コミットメントへ含める情報

中間値の整数列だけでなく、その解釈と実行条件もコミットメントへ含める。

```text
stage_id
format_version
session_id
rows / columns
scale / offset
algorithm_version
parameter_hash
input values
nonce
```

`parameter_hash`には、フィルタ係数、サンプリング周波数、SNR閾値、PCA特徴数、
VMDの`K`や`alpha`、呼吸帯域、同値時の選択規則などを含める。これにより、同じ
中間値を異なるアルゴリズム設定として解釈されることを防ぐ。

### 現在の実装との対応

- C0は生の複素CSIをPoseidonへ拘束する。
- C1はVMD入力をPoseidonへ拘束する。
- C1拘束付き証明書回路は、秘密のVMD入力と公開C1の一致を検証する。
- 縮約PCA射影回路は、入力行列・重みのコミットメントから射影結果の
  コミットメントへの内積計算を検証する。

ただし、現時点ではC0からC1までの全変換は接続されていない。特にSNR選択、
フィルタ、中心化、PCA重みの生成、最大固有値性は未証明である。

### 実装方針

すべてを1つの巨大なCircom回路へ入れるのではなく、処理ごとの回路へ分割する。
Pythonは高精度な値とwitnessを生成し、Circomは同じ入出力関係を制約として検証する。

```text
Python: X_(i+1) = f_i(X_i) を計算
Circom: 提示された X_i と X_(i+1) が同じ関係を満たすことを検証
```

したがって、Pythonで計算すること自体は信頼上の問題にならない。Pythonが誤った出力を
提示した場合に、有効な証明を生成できない回路になっていることが重要である。

### 推奨する追加順序

1. 全ステージ共通のコミットメント形式を固定する。
2. 現在のPCA射影回路を正式な入力・出力コミットメント遷移として扱う。
3. 複素CSIから振幅二乗への変換を追加する。
4. 固定小数点フィルタを追加する。
5. SNR計算とtop-k特徴選択を追加する。
6. PCA中心化、共分散、固有対の保証範囲を決める。
7. VMD証明書とBPM計算を接続する。
8. 必要に応じて複数証明を集約する。

### 残る設計判断

- PCA固有ベクトル算出そのものを証明するか、外部で与えた固有対の妥当性を証明するか。
- VMDの全反復を証明するか、再構成誤差・周波数条件を満たす証明書方式にするか。
- 各ステージをCircomで実装するか、反復処理だけzkVMへ分担するか。
- エッジデバイスではC0生成・署名まで行い、重い証明生成をサーバーへ委譲するか。

この議論では、最終目標を「すべてを単一回路で実行すること」ではなく、
「すべての処理が、連結されたどれかの証明によって検証されている状態」と定義した。
