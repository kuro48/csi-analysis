# 1. 背景とハイブリッド方針

全処理を回路化すると、固定小数点化・近似・巨大回路化により、呼吸推定精度と処理時間の両面に課題がある。

```text
実CSI → [C0] → Python: SNR・Filter・PCA・VMD
                       ↓ [C1: Poseidon]
                 Circom → Groth16検証
```

| Pythonが担当 | Circomが担当 |
|---|---|
| 浮動小数点の高精度処理 | 入力と公開C1の一致 |
| 既存の呼吸推定パイプライン | 呼吸数計算の制約検証 |
| 実験用特徴量の生成 | 縮約PCA射影の正当性 |

<span class="accent">高精度処理をPythonに残し、中間値のコミットメントでCircomへ連結する。</span>

---

# 2. C0／C1コミットメント仕様

Poseidonチェーンの仕様を固定し、PythonとCircomで同じ値を再現できるようにした。

```text
state₀ = Poseidon(domain_tag, nonce, format_version)
stateᵢ = Poseidon(stateᵢ₋₁, itemᵢ)
commitment = state_last
```

| 境界 | 対象 | 固定した仕様 |
|---|---|---|
| C0 | 生の複素CSI | I/Q順、scale=1000、offset=2³¹ |
| C1 | VMD入力 | signed値 + 2¹⁰ |

```python
nonce = new_commitment_nonce()
c0 = commit_raw_csi(csi_matrix, nonce)
c1 = commit_vmd_input(certificate_input["vmdInput"], nonce)
```

ドメインタグで用途を分離し、128-bit nonceは秘密入力として保持する。

# 3. C1拘束付き証明書回路

既存回路とは別に `csi_breathing_certificate_committed` を追加した。

```circom
encodedVmdInput[i] <== vmdInput[i] + 1024;
commitmentStep[i].inputs[0] <== commitmentState[i];
commitmentStep[i].inputs[1] <== encodedVmdInput[i];
commitmentState[T] === vmdCommitment;
```

この制約により、回路は次を保証する。

1. 秘密の `vmdInput` からC1を回路内で再計算
2. 再計算したC1と公開コミットメントが一致
3. C1を書き換えるとwitness生成時に拒否

新API：`POST /api/v2/breathing/analyze-committed`

# 4. 前処理検証を段階的に追加

32サンプル × 8特徴の、量子化したPCA射影回路を追加した。

```circom
projectionTerm[t][0] <== centeredX[t][0] * weights[0];
for (var n = 1; n < N; n++) {
  projectionTerm[t][n] <== centeredX[t][n] * weights[n];
  projectionPartial[t][n] <==
    projectionPartial[t][n-1] + projectionTerm[t][n];
}
projected[t] <== projectionPartial[t][N-1];
```

- PCA重みの絶対値上位8特徴を選択
- 入力行列・重み・射影結果をPoseidonで拘束
- Pythonの完全なPCA波形との相関を診断値として保存

<span class="small">現時点の保証範囲：縮約・量子化後の射影。SNR選択、フィルタ、最大固有値性は今後の候補。</span>
